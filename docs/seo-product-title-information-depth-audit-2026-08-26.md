# 产品标题信息层级扩展审计

## 目录字段审计

产品目录共 582 条记录。名称、材质和细度覆盖全部记录；既有标题规则已使用图案、领型、织法、人群、季节和尺寸。新增审计确认仍可安全利用的字段为颜色（582 条）、重量（180 条）和包装（78 条）。其中包装字段只有 69 条纱线记录包含可分离的 `100g cone / 500g hank` 单位；其余包装值含“custom packaging”、运输或优势宣传，因此不纳入标题。

目录中不存在独立的袖型、闭合、口袋、用途、场景、工艺或包装单位字段；不为这些不存在或不稳定的属性生成标题。颜色字段也会排除“多种颜色可选”、色卡、定制和营销文本，仅保留明确的单色词。纱线结构仅保留 single-strand、2-ply 或 3-ply 等实际结构词。重量字段排除 `Details`、`Description` 等占位符。

## 标题规则

产品 H1、Product Schema `name` 和面包屑末项继续共享同一扩充名称。规则的属性顺序为：名称、材质、细度、图案/领型/织法、颜色、纱线结构、筒纱/绞纱单位、重量、人群、季节和尺寸。HTML `<title>` 共享相同语义来源，并在本地化分类词和品牌尾缀之间以 128 字符上限裁剪，避免在搜索结果中无限拉长。

规则仍不输出认证、价格、MOQ、库存、样品、交期、产能、地区覆盖、定制承诺、色卡可用性或性能主张。Google 建议标题应准确、区别明确且避免关键词堆砌；本轮仅让真实且已列出的单品属性获得更完整的表达。[1](https://developers.google.com/search/docs/appearance/title-link)

## 构建验证

完整 Astro/Vercel 构建成功。六语产品详情输出继续保持零个重复标题、零个重复 H1、零个缺失 `<title>` 和正确 canonical。构建后所有语言中，实际 H1/标题的新增属性覆盖为：颜色 421 个、纱线结构 70 个、筒纱/绞纱包装 69 个、重量 146 个。实际搜索标题长度最高为 112 字符，平均长度为英文 105.9、德文 105.7、法文 106.2、日文 102.6、韩文 102.5、中文 96.7 个字符。产品 sitemap 仍为 3,522 个 URL，根级 API 入口仍为五个。

## 持续维护

后续要继续提高单品标题的信息量，应向产品记录新增稳定的、经核验的字段，例如袖型、闭合方式、口袋、织物组织、用途、包装单位或精确颜色；每个字段应为结构化值而非营销描述。标题构建器会以可审计方式消费这些字段，而不会把自由文本中的商业承诺带入 H1、Schema 或面包屑。
